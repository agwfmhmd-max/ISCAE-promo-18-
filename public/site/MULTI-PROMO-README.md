# نظام الدفعات المتعددة (Multi-Promo)

## الأدوار والعزل

| الدور | الصلاحية |
|---|---|
| **Superviseurs** — `agwfmhmd@gmail.com` (MDA) | ينشئ الدفعات ورؤساءها، ويدير أي دفعة بكامل صلاحيات المشرف الرئيسي السابقة. |
| **رئيس الدفعة** | صلاحيات المشرف الرئيسي داخل دفعته فقط، بما فيها رؤساء التخصصات والطلاب والبطاقات والإشعارات والإحصاءات والإعدادات والشعار. |
| **رئيس التخصص** | يبقى ضمن تخصصه ودفعتِه وفق صلاحياته السابقة. |

كل دفعة لها رقمها وشعارها الافتراضي المولّد من الرقم وإعداداتها وطلابها وتخصصاتها وحفلاتها وبطاقاتها وإشعاراتها واشتراكاتها وإحصاءات زياراتها. بيانات المشروع الحالية تُسند إلى الدفعة 18. يفرض Supabase نطاق الدفعة عبر RLS ودوال RPC، لا عبر تصفية الواجهة وحدها.

## التفعيل

1. احفظ نسخة مستقلة من المشروع قبل النشر. أُخذت قبل الترحيل لقطة داخل مخطط Supabase باسم `rollback_iscae_20261018` تشمل نسخ الجداول وبيانات الدوال والسياسات والقيود وبيانات حاوية الصور وسياساتها؛ لا تحذف هذا المخطط.
2. في **Supabase → SQL Editor** نفّذ `public/site/MULTI-PROMO.sql` كاملاً مرة واحدة. الملف محاط بمعاملة؛ إذا فشل أي جزء قبل `COMMIT` يُلغى التغيير. يربط حساب `agwfmhmd@gmail.com` كمشرف عام، ويُبقي سجلّه بلا `promotion_id`.
3. أضف إلى **Vercel → Project → Settings → Environment Variables** القيم التالية على الخادم فقط (لا تضعها في `public/site/index.html`):
   - `SUPABASE_SERVICE_ROLE_KEY` — مطلوب لوسيط الدفعات وإنشاء حسابات رؤساء الدفعات والتخصصات.
   - `SUPABASE_JWT_SECRET` — مطلوب لتوقيع رمز وصول قصير الأجل يحمل نطاق الدفعة.
   - `VERCEL_TOKEN` — مطلوب لإضافة نطاق كل دفعة آلياً. إذا كان المشروع ضمن فريق، أضف `VERCEL_TEAM_ID` أو `VERCEL_ORG_ID` بحسب سياق المشروع.
   - `VERCEL_PROJECT_ID` اختياري إن كان متغير Vercel التلقائي غير متاح؛ اسم المشروع الافتراضي في الشيفرة `iscae-promo-18`.
   - احتفظ بمتغيرات Push القائمة: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
4. انشر نسخة الشيفرة المحدّثة على مشروع Vercel **بعد** نجاح ترحيل Supabase. لا تترك الموقع القديم يعمل على المخطط الجديد؛ الواجهة القديمة لا ترسل رمز الدفعة.
5. بحساب Superviseurs افتح **الدفعات → إنشاء دفعة جديدة**، أدخل الرقم (مثلاً 19)، ويمكنك إنشاء رئيس الدفعة معها. تُنشأ الإعدادات والشعار الافتراضي تلقائياً. الرابط الرسمي المقترح `iscae-promo-19.vercel.app` يُربط آلياً عند توفر صلاحية Vercel؛ وإلا يظهر رابط مؤقت `?promo=19` مع تعليمات الربط اليدوي.

## النطاقات

يستخرج الموقع رقم الدفعة من `iscae-promo-N.vercel.app` أو من قيمة النطاق المسجلة في `promotions.domain`. تغيير الدفعة عبر `?promo=N` مسموح فقط عندما تعذّر ربط النطاق (`domain_status=manual`) أو على `localhost`. الدفعة غير الموجودة تعرض رسالة واضحة، ورئيس الدفعة يُرفض من نطاق دفعة أخرى. مشروع Vercel المتصل أظهر حالياً النطاق `iscae-promo-18-eight.vercel.app`؛ يبقى مدعوماً كاسم للدفعة 18، بينما `iscae-promo-18.vercel.app` يحتاج أن يكون مربوطاً فعلياً بهذا المشروع من لوحة Vercel.

## التراجع عند تعطل النسخة

- **إذا فشل تطبيق SQL نفسه:** المعاملة في `MULTI-PROMO.sql` تجعل التغيير ذرياً؛ لا تُعدّل الواجهة ولا تحذف مخطط اللقطة. راجع سبب الخطأ ثم أعد المحاولة فقط بعد تصحيحه.
- **إذا نجح SQL وفشلت الشيفرة الجديدة:** أوقف إنشاء دفعات/حسابات جديدة، واحتفظ ببيانات أي دفعة أُنشئت بعد الترحيل. أعِد نشر إصدار Vercel السابق عند الحاجة؛ ولأن المخطط الجديد يغيّر RLS ورموز الوصول، فإن الإرجاع الكامل إلى الشيفرة القديمة يتطلب أيضاً استعادة قاعدة Supabase إلى ما قبل الترحيل من نسخة/PITR متاحة، أو استعادة عناصرها من اللقطة `rollback_iscae_20261018` بواسطة مسؤول قاعدة البيانات. لا تحذف أعمدة أو سياسات يدوياً ولا تحذف مخطط اللقطة. بعد استعادة قاعدة البيانات، أعد نشر النسخة السابقة وتحقق من تسجيل الدخول وقراءة البيانات قبل فتح الموقع للزوار.
